# 莫奈数字讲解员：整体脉络、对话流程、API 与 WebSocket

服务入口：`server9`（对外版本号 v8.5.0）  
默认地址：`http://<主机>:8848`  
Swagger：`http://<主机>:8848/docs`  
健康检查：`GET /health`

本文以 **当前代码** 为准。根目录 `ROBOT_API.md` 仍是旧协议（hello/bye、HTTP 回调、本机音箱），请勿按旧文档联调。

---

## 1. 项目是什么

这是跑在 Windows 上的 **莫奈数字讲解员**：检索本届展知识库，以克洛德·莫奈第一人称改写，再用 CosyVoice 合成语音。

同时服务两类客户端：

| 客户端 | 通道 | 声音怎么走 |
|--------|------|------------|
| 展厅游客前端 | `/ws/chat` | 整句 Base64 WAV |
| Unity / 展项播报 | `/ws/tts` | 流式 PCM（24kHz） |
| 场馆机器人 | `POST /api/robot/ask` | 不直接播音；讲解员把字幕和 PCM 推到所有 `/ws/tts` 连接 |

知识边界很硬：**只讲眼前这场莫奈展**。问别的展会/博物馆会拒答；LLM 稿子一旦越界，立刻改口「这个我还不太清楚…」。请求里的 `category` 会被忽略，始终只查 `exhibition_monet`。

## 2. 整体架构

```text
游客前端 / Unity          场馆机器人
   |                         |
   |  WS /ws/chat            |  HTTP POST /api/robot/ask
   |  WS /ws/tts             |  （立刻 202，后台开讲）
   v                         v
           FastAPI (server9/app.py :8848)
                    |
     +--------------+--------------+
     |              |              |
  RAG 检索      本地 LLM        CosyVoice TTS
  FAISS+BM25    llama.cpp       分句 PCM
  只查本届展    :8080           24kHz
```

| 模块 | 路径 | 职责 |
|------|------|------|
| 启动与路由 | `server9/app.py` | CORS、HTTP / WS 注册、健康检查 |
| 配置 | `server9/config.py` | 路径、阈值、端口、机器人参数 |
| 检索 | `server9/rag/` | 向量 + BM25 + RRF，锁定本届展 |
| 人设与 LLM | `server9/llm/` | 调 llama.cpp，洗 think、防串台 |
| 语音 | `server9/tts/cosyvoice.py` | CosyVoice2-0.5B，分句流式 PCM / 整段 WAV |
| 会话 | `server9/session.py` | 对话历史、落盘 `sessions/`、超时清理 |
| 机器人 | `server9/robot/` | 会话、一轮编排、往 `/ws/tts` 推流 |
| WebSocket | `server9/ws/` | 游客对话、游客 TTS、机器人广播 |

依赖服务：

| 服务 | 地址 / 路径 | 说明 |
|------|-------------|------|
| 本服务 | `0.0.0.0:8848` | 可用 `MONET_HOST` / `MONET_PORT` 覆盖 |
| LLM | `http://127.0.0.1:8080/v1/chat/completions` | llama.cpp，`temperature=0.05`，`max_tokens=300` |
| TTS | CosyVoice2-0.5B | 说话人默认「中文男」，采样率 24000 |
| 记忆服务 | 默认关闭 | `ENABLE_MEMORY=False`，避免与 8080 冲突 |

## 3. 对话流程

系统有三条通道，检索和人设共用，**送出方式不同**。

### 3.1 通道 A：游客讲解 `/ws/chat`

适合需要会话记忆、意图分流、推荐的讲解端。

```text
连上 /ws/chat
  → 首包 {user_id, session_id?} → 返回 init
  → 循环收 {question, enable_audio, speaker, ...}

每轮：
  1. 若与当前机器人 ask 原文相同 → 忽略（防 asr 回声）
  2. 问其他展会 → 拒答 + 可选整段 WAV
  3. 意图分类
       command  → 暂停 / 音量 / 再说一遍（规则回复）
       chitchat → 你好 / 你是谁 / 再见（规则回复）
       knowledge → 检索 + 流式 LLM
  4. 知识轮：命中则流式推 type=text，按句合成 type=audio
     未命中 / 越界 → REFUSE_TEXT
  5. 可追加钩子句、票务、推荐
  6. type=done 收尾，会话写入 sessions/
```

游客 TTS 走的是 **整句 Base64 WAV**（`type=audio`），不是 PCM 分片。

### 3.2 通道 B：展项播报 `/ws/tts`

这是展项真正播声音的主通道。游客自己提问，和机器人推流，**共用同一条连接、同一套消息类型**。

游客主动一轮：

```text
客户端发 {type:"tts", text, speaker, enable_llm}
  → tts_start（pcm / 24kHz / 单声道 / 16bit）
  → llm_answer（全文；enable_llm=true 时在生成结束后发）
  → tts_sentence + tts_chunk（逐句字幕 + PCM）
  → tts_end
```

也可 `{type:"cancel"}` 打断本连接上的游客合成；`{type:"ping"}` 心跳。

### 3.3 通道 C：机器人 `POST /api/robot/ask`

机器人不直接播音。讲解员检索、改写、合成后，**广播到所有已连接的 `/ws/tts` 客户端**。Unity 展项必须事先连上并保持不断。

```text
机器人 POST /api/robot/ask {query, robot_id, session_id?}
        │
        ├─ busy? → 409 turn_in_progress
        ├─ 无会话 → 自动新建 robot_{时间}_{随机}
        └─ 立刻 HTTP 202 {session_id, request_id, accepted:true}
                │
                └─ 后台任务：
                     告别语（再见 / 拜拜…）→ 固定再见稿
                     否则 RAG + LLM 改写
                     然后推 /ws/tts：
                       asr → tts_start → llm_answer
                         → 逐句 tts_sentence / tts_chunk
                         → 等到 PCM 时长 + 0.25s 尾音
                         → tts_end
                     mark_idle；告别则释放会话
```

硬规则（以代码为准）：

1. `202` 只表示已受理，讲解在后台进行；**不再 HTTP 回调 `turn_end`**。
2. 本轮 `busy` 时再 ask，返回 `409 turn_in_progress`。
3. 声音 **只走 `/ws/tts`**，不走本机声卡；`play_local` / `wait` 已废弃或忽略。
4. 机器人推流期间：忽略游客 `type=tts` 和 `type=cancel`，避免双流叠播。
5. 问句里带「再见 / 拜拜 / 告辞 / 回头见 / 下次见 / 我走了 / 先走了 / 走了啊 / 不聊了」：播完告别稿后释放会话。
6. 空闲超过 **120 秒** 自动释放（`idle_timeout`）。
7. `ROBOT_MAX_ROUNDS` 仍记在状态里，当前 `acquire()` **不再用它拒绝后续 ask**。
8. 后来的 ask 在空闲时会直接续接，**不再因换 `robot_id` 而 409**。

### 3.4 一轮知识问答的内部管线

游客知识轮和机器人 ask 共用：

```text
问题
  → 其他展会？直接拒答
  → 指代消解（会话实体）
  → FAISS 向量 Top50 + BM25 Top50 → RRF 融合
  → 只保留 category=exhibition_monet
  → 分数 < 0.015（无 rerank）则拒答
  → 资料压缩后交给 LLM（SYSTEM_PROMPT = 莫奈第一人称）
  → 清洗 think / 串台词 / 开场白
  → 答案再扫一遍，越界则改口
  → TTS 分句合成
```

拒答文案（`REFUSE_TEXT`）：

> 这个我还不太清楚。我只讲解眼前这场展，你可以问我睡莲、《日出·印象》，或展厅里的其他展品。

## 4. HTTP API

默认 `http://<主机>:8848`。若配置了 `ROBOT_API_TOKEN`，机器人请求需带请求头 `X-Robot-Token`。

### 4.1 通用

#### `GET /health`

返回索引条数、TTS 状态、会话数、机器人快照、`/ws/tts` 连接数。

```json
{
  "status": "healthy",
  "chunks": 0,
  "vectors": 0,
  "tts": true,
  "sessions": 0,
  "robot": {
    "active": false,
    "session_id": null,
    "robot_id": null,
    "round": 0,
    "max_rounds": 3,
    "busy": false
  },
  "tts_ws_clients": 0
}
```

#### `POST /search`

检索调试。命中其他展会时 `refused=true`。`category` 实际被忽略。

请求：

```json
{
  "query": "睡莲是在哪里画的？",
  "top_k": 2,
  "category": null
}
```

#### `POST /tts`

同步整段 WAV（Base64）。正文越界会改口拒答。

请求：

```json
{
  "text": "欢迎来到我的世界。",
  "speaker": "中文男"
}
```

成功：`{"audio": "<base64>", "format": "wav"}`  
失败：`{"error": "..."}`

### 4.2 机器人（当前只保留 ask）

#### `POST /api/robot/ask`

请求：

```json
{
  "query": "睡莲是在哪里画的？",
  "robot_id": "robot-01",
  "session_id": null,
  "include_audio": true,
  "speaker": "中文男",
  "top_k": 2
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `query` | 是 | 观众 / 机器人问题 |
| `robot_id` | 否 | 默认 `default` |
| `session_id` | 否 | 不填则新建；续接时可带回上一轮 id |
| `include_audio` | 否 | 默认 true；后台仍会组一份 WAV，但前端播报只认 `/ws/tts` |
| `wait` | 否 | **已忽略**：一律立刻 202 |
| `play_local` | 否 | **已废弃**，声音只走 `/ws/tts` |
| `speaker` | 否 | 默认「中文男」 |
| `top_k` | 否 | 默认 2 |
| `category` | 否 | **已忽略**，始终只检索本届展 |

立刻返回（默认 202，可用 `ROBOT_ACCEPTED_STATUS=200` 改成 200）：

```json
{
  "ok": true,
  "code": "accepted",
  "accepted": true,
  "done": false,
  "action": "ask",
  "session_id": "robot_1789…",
  "request_id": "…",
  "robot_id": "robot-01",
  "round": 0,
  "can_continue": true,
  "next_hint": "ask",
  "text": "",
  "refused": false,
  "sources": [],
  "message": "已受理。讲解在后台进行。"
}
```

请保存 `session_id`，后续 ask 可带上（不带也会在空闲时自动续接当前会话）。

错误码：

| HTTP | code | 含义 |
|------|------|------|
| 401 | — | `X-Robot-Token` 不正确 |
| 409 | `turn_in_progress` | 上一轮还在讲，等 `/ws/tts` 的 `tts_end` 后再发 |
| 422 | — | `query` 为空 |

旧文档里的 `/api/robot/hello`、`/bye`、`/status`、`/push/*` 以及向机器人 POST `on_turn_end` / `on_session_end`，**当前代码里已经没有了**。会话靠 ask 自动创建，靠告别语或空闲超时释放。

## 5. WebSocket

### 5.1 `/ws/tts` — 展项播报主通道

地址：`ws://<主机>:8848/ws/tts`  
连接后服务端先发：

```json
{"type": "ready", "service": "monet-tts-stream"}
```

机器人广播走 `tts_fanout`：所有 `/ws/tts` 连接都会收到同一轮流。单条发送超时 8 秒，失败则摘掉死连接。机器人开口前会打断游客正在播的 TTS。

#### 客户端 → 服务端

| type | 字段 | 说明 |
|------|------|------|
| `tts` | `text`, `speaker`, `enable_llm` | 游客提问；机器人 `busy` 时被忽略 |
| `cancel` | — | 取消本连接游客合成；机器人 `busy` 时忽略 |
| `ping` | — | 回 `pong` |

游客提问示例：

```json
{
  "type": "tts",
  "text": "睡莲是在哪里画的？",
  "speaker": "中文男",
  "enable_llm": true
}
```

#### 服务端 → 客户端

游客自己问，或机器人广播，消息类型相同。机器人轮每条都会带 `robot_id`。

| type | 关键字段 | 时机 |
|------|----------|------|
| `asr` | `text`, `session_id`, `robot_id` | 仅机器人轮：把提问词同步到前端字幕 |
| `tts_start` | `format=pcm`, `sample_rate=24000`, `channels=1`, `sample_width=2`, `text` | 一轮一次，给 Unity 建播放器 |
| `llm_answer` | `text` | 机器人轮紧跟 start；游客轮在 LLM 结束后 |
| `tts_sentence` | `index`, `text` | 逐句字幕 |
| `tts_chunk` | PCM 分片 | 按播放节奏推，缓存命中也不会瞬间倒完 |
| `tts_end` | `seq_count`, `sentence_count`, `cancelled` | 一轮一次；机器人轮会等到 PCM 时长再发 |
| `error` | `message` | 失败 |
| `cancel_ack` | — | 游客 cancel 确认 |
| `pong` | — | 心跳回复 |

机器人一轮标准顺序：

```text
asr → tts_start → llm_answer → tts_sentence / tts_chunk… →（等 PCM 时长）→ tts_end
```

约束：

- `tts_start` / `tts_end` 各一次
- `llm_answer` 紧跟 `tts_start`，不再等合成结束
- `tts_start` 发出后会再等 **200ms**，给 Unity 建播放器
- `tts_end` 按音频真实时长 + `ROBOT_PLAY_TAIL_SEC`（默认 0.25s）发送
- 前端切勿在收到 `asr` / `llm_answer` 后再回一条 `type=tts`，否则会和 robot 流抢同一条连接

`tts_start` 示例：

```json
{
  "type": "tts_start",
  "session_id": "robot_1789…",
  "format": "pcm",
  "sample_rate": 24000,
  "channels": 1,
  "sample_width": 2,
  "text": "我在吉维尼的花园里种了一整片睡莲。",
  "robot_id": "robot-01"
}
```

### 5.2 `/ws/chat` — 游客讲解对话

地址：`ws://<主机>:8848/ws/chat`

| 方向 | type | 说明 |
|------|------|------|
| C→S 首包 | `user_id`, `session_id` | 恢复或新建会话 |
| S→C | `init` | 回 `session_id`、历史条数、`resumed` |
| C→S | `question`, `enable_audio`, `speaker`, `top_k` | 每一轮问题 |
| S→C | `text` | 流式文本增量 |
| S→C | `audio` | 整句 WAV Base64（`sentence`, `index`） |
| S→C | `recommendation` | 达到轮次后推荐展品 |
| S→C | `done` | `refused` / `intent` / `sources` / `sentiment` |
| S→C | `error` | 错误 |

首包：

```json
{"user_id": "guest-01", "session_id": null}
```

`init` 回包：

```json
{
  "type": "init",
  "session_id": "session_…",
  "user_id": "guest-01",
  "preferences": {},
  "history_count": 0,
  "resumed": false
}
```

提问：

```json
{
  "question": "日出印象是怎么来的？",
  "enable_audio": true,
  "speaker": "中文男",
  "top_k": 2
}
```

`done` 示例：

```json
{
  "type": "done",
  "refused": false,
  "intent": "knowledge",
  "sources": ["item_…"],
  "suggestions": [],
  "sentiment": {"label": "neutral", "score": 0.0, "keywords": []}
}
```

`intent` 取值：`command` / `chitchat` / `knowledge`。

## 6. 环境变量

可在启动前设置，不必改代码。

```powershell
$env:MONET_HOST = "0.0.0.0"
$env:MONET_PORT = "8848"
$env:ROBOT_API_TOKEN = "replace-me"
$env:ROBOT_IDLE_TIMEOUT = "120"
$env:ROBOT_ACCEPTED_STATUS = "202"
python -m server9.app
```

实际启动以项目现场命令为准，入口在 `server9/app.py` 的 `run()`。

| 变量 | 默认 | 说明 |
|------|------|------|
| `MONET_HOST` | `0.0.0.0` | 监听地址 |
| `MONET_PORT` | `8848` | 监听端口 |
| `ROBOT_API_TOKEN` | 空 | 非空则机器人请求必须带 `X-Robot-Token` |
| `ROBOT_IDLE_TIMEOUT` | `120` | 轮次间隔超时（秒），超时释放会话 |
| `ROBOT_MAX_ROUNDS` | `3` | 仍写入状态快照，当前不用于拒绝 ask |
| `ROBOT_ACCEPTED_STATUS` | `202` | ask 受理状态码，可改为 `200` |
| `ROBOT_PLAY_TAIL_SEC` | `0.25` | 推完 PCM 后再等的尾音（秒），然后才发 `tts_end` |
| `ROBOT_LOG_LEVEL` | `DEBUG` | 机器人相关日志级别 |

## 7. 现场联调要点

1. **Unity / 展项必须先连 `ws://主机:8848/ws/tts` 再让机器人 ask**，否则 HTTP 202 成功但前端无声（日志会警告 `ws_pushed<=0`）。
2. 机器人侧以 HTTP 202 为准，不要等讲解员再 POST 回来。
3. 本轮没结束不要连发 ask；等前端收到 `tts_end`，或等 `GET /health` 里 `robot.busy=false`。
4. 前端收到 robot 的 `asr` / `llm_answer` 后不要再发 `type=tts`。
5. 可用联调脚本：

```powershell
python scripts/test_robot_ask.py
python scripts/test_robot_ask.py --host 127.0.0.1 --port 8848 --robot-id robot-001
python scripts/test_robot_ask.py --query 莫奈介绍下自己吧
```

默认三轮：介绍自己 → 有哪些作品 → 介绍睡莲。  
通过条件：HTTP 202、`tts_start` / `tts_end` 各 1 次、`llm_answer` 在 `end` 之前、有音频分片。

`--echo-tts` 会在收到 `llm_answer` 后再发 `type=tts`，用来复现双流问题，联调时不要开。

正常日志应类似：

```text
已推 asr / tts_start / llm_answer
⏭ 忽略游客 TTS（机器人正在推流）   # 若前端仍回声
开始逐句 TTS / 缓存命中按播放节奏推流
等播报结束再 tts_end
已推 tts_end  tts_wall≈pcm 时长
```

不应再出现：robot 推流过程中夹一行 `🤖 用户问题: 我是克罗德…`（那是讲稿被当成游客新问题）。

## 8. 和旧文档的差异

| 旧协议（`ROBOT_API.md`） | 当前代码 |
|--------------------------|----------|
| `POST /api/robot/hello` / `bye` / `status` / `push/*` | 已删除，只保留 `POST /api/robot/ask` |
| 本机音箱播放，讲完后 HTTP 回调 `turn_end` | 声音只走 `/ws/tts`，不回调机器人 |
| 独占期间拒绝游客 `/ws/tts`、`/ws/chat`、`POST /tts` | 游客连接仍可用；busy 时忽略游客 `tts` / `cancel` |
| 满 3 轮返回 `409 max_rounds` | 轮次计数仍在，不再据此拒绝 |
| 换 `robot_id` 可能 `409 robot_busy` | 空闲时直接续接 / 接管 |
| `wait=true` 可阻塞到讲完 | `wait` 已忽略，一律立刻 202 |

更细的推流改动见 `robot-ask-ws-改动说明.md`。
