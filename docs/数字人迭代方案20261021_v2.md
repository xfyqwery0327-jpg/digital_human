# 数字人迭代方案 v2

日期：2026-10-21  
依据：`docs/数字人迭代方案20261021_v1.txt`，对照当前 `server9` 与 `personas/`  
范围：游客讲解的意图、口播、引导按钮、展品名。不改 TTS 引擎，不改权重。

## 结论

v1 的产品规则可以留：先认意图，实时问题只答一句再拉回本厅，知识问题只讲检索到的内容，引导不写进口播，展品名单独给前端，口播跟用户语言走。

v1 的落地方式不能留。它让 4B 一次吐出整段 JSON，再把 9 条示例塞进系统提示词。现在的讲解是边生成边切句、边合成。模型一旦输出字段名和括号，语音会把 JSON 念出来。`n_ctx` 是 2048，`max_tokens` 游客侧约 300、机器人短答 128，装不下这份提示词。

v2 把一条回答拆成两条通道：

- 口播只保留现在的纯文本。系统提示词继续放在各人设 YAML 里，模型不输出 JSON。
- 意图、引导按钮、展品名、语种由服务端填，挂在 WebSocket 的 `done` 上。前端拿去画按钮和高亮，不送进 TTS。

第一期只做中文。天气和新闻没有数据源时不报具体气温、不报头条，用固定句子拉回本厅。英、日、韩和真实天气插件放到后面，避免在现有中文音色上假做多语种。

## v1 里要修的问题

示例 5 的 JSON 不合法：`"lang"` 写了两次，前一个值是 `"exhibition"`。按 v1 自己的 schema，`lang` 只能是 `zh | en | jp | kr`，`intent` 才是 `exhibition`。

示例里的钩子全是莫奈画作。仓库里同时在跑三个人设，默认人设仍是莫奈，另外还有妇好、鸠摩罗什。同一段提示词贴进三个人，妇好会被带去讲睡莲。

v1 假设「外部插件返回实时数据」。代码里没有天气或新闻接口。Qwen3-TTS 合成语言写死为 `Chinese`，`to_spoken_zh` 会把数字改成中文读法。这两条都还没准备好多语种口播。

## 和现况的差距

| v1 要求 | 现在实际 | v2 怎么做 |
| --- | --- | --- |
| 6 类意图由模型写在 JSON 里 | 向量分类，只有 `command` / `chitchat` / `knowledge`，阈值在人设例句上 | 分类仍放服务端。扩展标签，不让模型在口播里报类别 |
| 天气、新闻短答后拉回展品；连续第二轮加强收敛 | 没有这两类，也没有轮次计数 | 无插件时用固定短句。会话里记连续次数 |
| `hook_suggest` 1～2 条，给前端按钮 | `hooks` 在第 1 轮和之后每 3 轮**念出来**，并写进回答正文 | 停止念钩子。从该人设的 `hooks` 里选 1～2 条放进 `done` |
| `art_names` 只给前端，口播里不加粗、不单列 | 没有这个字段。展品名混在口播里。检索另有莫奈作品提示 | 用人设索引的 `title` 做白名单，从口播里对齐，不另开一次生成 |
| 中 / 英 / 日 / 韩同语回复 | 口播链路按中文处理 | 第一期 `lang` 固定 `zh`。其他语言单独立项 |
| 只返回纯 JSON | 游客通道是 `text` 增量、`audio`、最后 `done`。机器人 `/api/robot/ask` 要的是可念的纯文本 | 游客 `done` 增加控制字段。机器人应答保持纯文本 |
| 空检索不编造 | 已有拒答：`refuse_text`、本厅锁定、串人设拦截 | 保持。实时类不走检索，避免空库时胡编气温 |
| 画作译名对照表 | 没有 | 第一期不做。中文专名以索引标题为准 |

当前口播提示词已经写清了更硬的约束，v2 不推翻：第一人称、2～4 句、开口就是答案、年代和件数用中文数字、资料没有就不编、不讲别的展和其他数字人。妇好、鸠摩罗什还有「不要每句自我介绍」和开头套话剥离。这些继续留在 YAML 里。

## 通道分工

```text
用户问题
  → 服务端认语种（第一期只收中文）
  → 服务端认意图（向量分类 + 实时类词表）
  → command / chitchat / weather / news：固定句子，不调用大模型
  → exhibit / person / visit：只查当前人设的索引，命中后才流式生成口播
  → 口播按句推给 TTS（与现在相同）
  → 本轮口播结束后，服务端填 hook_suggest、exhibit_names
  → done 一次发给前端
```

模型看到的用户消息保持现在的形状：参考资料、对话历史、问题、`/no_think`。不要把 schema、few-shot 和插件原文再贴进去。

## 意图

服务端标签用来路由。`done.intent` 用下面这组，前端不必再猜 v1 的字符串。

| 标签 | 对应 v1 | 路由 |
| --- | --- | --- |
| `command` | v1 没有，现场需要 | 暂停、再说一遍、声音大小。保持现有指令表 |
| `chitchat` | `chat_other` | 你好、你是谁、谢谢、再见。走人设 `chitchat`，不检索 |
| `weather` | `weather` | 不检索、不调用大模型 |
| `news` | `news` | 不检索、不调用大模型 |
| `exhibit` | `art_work` | 检索本厅展品、画作、器物、经名 |
| `person` | `artist` | 检索本人相关生平，仍限本厅资料 |
| `visit` | `exhibition` | 开放时间、闭馆、展厅位置、票务。优先人设 `ticket_info`，不够再检索 |
| `knowledge` | 兜底 | 分类把握不住时，沿用现在的检索路径 |

分类器仍用各人设 `intent_examples` 的向量，不为了 v1 改成让模型分类。每个 YAML 补 `weather`、`news`、`exhibit`、`person`、`visit` 的例句。`command` 和 `chitchat` 保留。旧的 `knowledge` 例句并进 `exhibit` 与 `person`，避免一件器物和一句寒暄抢同一个向量。

实时类用词表兜底，不单靠向量。例如「天气」「气温」「下雨」「新闻」「头条」。词表命中且不是在问展品名称时，直接进 `weather` 或 `news`。

连续两轮规则记在会话上，按人设分开计：

- 第 1 轮：一句短答，加 1 条拉回本厅的钩子。
- 第 2 轮起：口播改为该人设的收敛句，钩子仍是 1 条本厅问题。
- 中间一旦问了展品、人物或参观，计数清零。

没有插件数据时，第 1 轮也不要报气温和头条。三个人设各写自己的句子，禁止共用莫奈示例。

| 人设 | 第 1 轮口播 | 第 2 轮起口播 | 钩子指向 |
| --- | --- | --- | --- |
| 莫奈 | 场馆里不播报天气和新闻。今天更适合在厅里看光和颜色。 | 天气和新闻就到这里。厅里还有作品可以看。 | 睡莲、《日出·印象》 |
| 妇好 | 场馆里不播报天气和新闻。今日只讲这一场商代的展。 | 这件事就到这里。厅里的甲骨和青铜可以继续看。 | 甲骨、青铜、玉器 |
| 鸠摩罗什 | 场馆里不播报天气和新闻。今日只讲这一场龟兹的展。 | 这件事就到这里。厅里的译经和造像可以继续看。 | 译经、舍利盒、造像 |

以后接上插件，只允许把插件给的一句事实填进第 1 轮模板，例如「今日晴，二十二到二十八摄氏度」。事实句子仍由模板拼接，不交给模型扩写。第 2 轮起继续用收敛句，不重复播报。

## 钩子

钩子是按钮文案，不是下一句台词。

- 每轮 1～2 条，短到能放进按钮。
- 文案从当前人设的 `hooks` 里取，用过的放进 `session.hook_used`，池子空了再回头用。
- 选择跟意图走，不再按对话轮数随机念 `deep` / `technique`：
  - `exhibit`：创作或出土背景、同厅其他一件
  - `person`：生平里的下一段，或本厅一件代表器物
  - `visit`：开放时间、展厅位置、一件亮点
  - `weather` / `news`：拉回本厅，只用 1 条
  - `chitchat`：1 条本厅入口问题
- 口播正文不再追加钩子，也不再把票务促销句自动接在回答尾巴上。票务只在 `visit` 且问题里出现票、价格、展期、位置时说，说的是 `ticket_info` 里已有的句子。
- `done` 里原有的 `suggestions` 继续表示「推荐展品」。`hook_suggest` 表示「下一问按钮」。两个字段不要混用。

## 展品名

字段名用 `exhibit_names`，不再叫 `art_names`。妇好的青铜、鸠摩罗什的舍利盒都不是画作。莫奈厅里它就是画作名。

对齐顺序：

1. 用当前人设 `items.json` 的 `title` 做白名单，在本轮口播里查找出现过的标题。
2. 标题的简称写进人设别名表后再匹配，例如「日出印象」对上「日出·印象」。别名只加本厅真实在展的名字。
3. 对不上的不收。不用 jieba 词性，也不要模型再抽一次。jieba 会把普通名词收进来。
4. 口播保持自然说出名字。不要加粗，不要在句尾再念一遍名单。

空检索或拒答时，`exhibit_names` 为 `[]`。

## 协议

游客 WebSocket 的 `text`、`audio` 不变，内容只许是口播。`done` 增加三个字段：

```json
{
  "type": "done",
  "refused": false,
  "intent": "exhibit",
  "lang": "zh",
  "hook_suggest": ["想听听这幅画是在哪里画的吗？"],
  "exhibit_names": ["睡莲"],
  "sources": ["item-id"],
  "suggestions": [],
  "sentiment": {"label": "neutral", "score": 0.5, "keywords": []}
}
```

约束：

- `hook_suggest` 最多 2 条。实时类最多 1 条。
- `lang` 第一期恒为 `zh`。
- `exhibit_names` 里的字符串必须等于该人设索引标题或别名表指向的标题。
- 机器人 `/api/robot/ask` 和模式 2 固定讲稿不增加这些字段，回答仍是纯文本。机器人屏幕若要按钮，单独加可选字段，默认不填、不念。

## 分期

### 第一期：把 v1 收成可用协议

只改讲解对话，不动 CosyVoice / Qwen 合成，不动显存释放。

1. `personas/*.yaml` 补意图例句、实时收敛句、展品别名。三份各写各的，不复制莫奈画名。
2. `rag/intent.py` 增加 `weather`、`news`、`exhibit`、`person`、`visit`。实时词表优先于向量。
3. `ws/chat.py`：这四类固定句直接返回；知识类仍走现有检索和流式生成。
4. 去掉「把 hook 拼进口播并送去合成」。`done` 带上 `hook_suggest`、`exhibit_names`、`lang`。
5. 会话增加实时类连续计数，第二轮换收敛句。
6. 用 v1 的 9 个中文场景改写成验收用例。英文、日文、韩文用例标成第二期，不作为这一期失败条件。

验收时看四件事：耳机里没有括号和字段名；连续两次问天气，第二次是收敛句且没有编造气温；问睡莲时 `exhibit_names` 含索引里的标准标题；妇好被问莫奈时仍拒答，不会推荐睡莲。

### 第二期：实时数据

有确定的天气、新闻来源后再做。插件只提供一句可核对的事实，模板拼接后口播。失败、超时、空结果退回第一期的「场馆里不播报」句子，不让模型补。新闻只取与到馆相关的一句，不展开时事。

### 第三期：多语种

要同时有四样东西才开：语种识别、各语言口播（不能再走 `to_spoken_zh`）、对应音色、展品标准译名表。在这之前，非中文输入用中文说明「现在只用中文讲解」，`lang` 仍为 `zh`，不要用中文音色念日文或韩文句子。

## 不做什么

- 不把 v1 全文贴进 `system_prompt`，也不要模型输出 JSON。
- 不把莫奈 few-shot 配给妇好和鸠摩罗什。
- 不在没有插件时让模型编写天气和新闻。
- 不在第一期改 TTS 批大小、显存释放和机器人模式 2 / 模式 3 的字数。
- 不把钩子、票务促销、推荐展品三句话叠在同一段口播末尾。
