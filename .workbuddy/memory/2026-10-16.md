## CosyVoice3 卡顿 + 静音问题排查与修复（莫奈数字讲解员 / server9）
- 现象：CV3 出声卡顿、说几句后彻底没声；CV2 正常。
- 根因（卡顿）：CV3 每句 RTF≈13~28（CV2 仅 1~2），预热「GPU 未生效 RTF=17.18」。
  - CV3 继承 CosyVoice2Model，`token2wav`(model.py:425) 每跳都重跑整段 10 步扩散
    （`tts_mel[:, :, token_offset*ratio:]` 丢弃前缀 → O(N²)），且 `stream=True` 的
    flow 解码在首跳之后吐静音切片 → 日志大量「丢弃全 0 PCM 分片」。
- 根因（静音）：`KeyError: <uuid>`（日志 11:03:42）是二次症状——主循环 finally pop 掉
  uuid 字典后，仍在跑的 LLM 线程再访问该键即抛错 → 整轮静音（整句无有效 PCM）。
- 重要修正：之前补 `mel_overlap_dict/flow_cache_dict` 初始化的改动对 CV3 是 no-op
  （CosyVoice3Model 根本不创建这两个属性，hasattr 为 False 被跳过）。保留它无妨
  （对基类 CosyVoiceModel 有用），但不是 CV3 的关键修复。
- 关键修复（`_cv3_tts_nonstream`）：CV3 改走库自带 `model.tts(stream=False)` 整句单遍
  finalize=True（model.py:375-387）。委托库管理 uuid 状态，绕开 KeyError；单遍扩散
  干净整句音频、整体耗时约降为流式 1/(句长/跳长) 倍（预计 RTF 从 ~17 降到 ~1.x）。
  `_yield_tts_stream` 仅 CV2 走，完全不动。新增环境变量 `MONET_CV3_NONSTREAM`（默认 1，
  设 0 回退增量流式调试）。改动在 cosyvoice.py，py_compile 通过。
- 待运行验证：需把 `deploy/cosyvoice.model` 切到 CV3 并重启服务，观察预热 RTF 是否降到
  ~1、日志是否不再出现「丢弃全 0 PCM」「整句无有效 PCM」「TTS LLM 线程失败 KeyError」。
- 4070 能否跑 CV3：能。RTX 4070 12GB GDDR6X / Ada sm_89 / fp16~588 TFLOPS。CV3-0.5B
  权重 fp16 ~1-1.5GB + 极小 KV 缓存，VRAM 充裕；fp16 与 cuda 早已开启（cosyvoice.py:1293/
  1321）。慢是软件 bug 不是硬件。当前 11.1GB/12GB 占用主要是 Windows WDDM 显示分配，
  切 CV3 不会显著增加。
- 权衡：非流式首包延迟变高（整句算完才出声），但换来干净不卡；如需低延迟可后续改小句
  或修好增量缓存。线上当前为 CV2（好状态），未自动重启。

  - 非流式下「首包延迟」= 整句推理耗时，与 RTF 一致（不是独立卡顿）。
- 根因（卡顿/超时）：CV3 在 **Windows + WDDM** 下自回归 LLM 每 token CUDA 同步开销极大，
  实测 ~80ms/token → RTF 4~11（0.5B 模型本应 <1~2）。这是「GPU 未生效 RTF=17」的真因，

  （llm_job 是线程非进程；model.tts 每句 empty_cache）。
- 结论：4070 能「跑」CV3（已确认），但**纯 Windows 下达不到实时**（回合要数分钟）。
  实测对比：本场 CV3 非流式 RTF 3.9~11（较此前流式 13~28 已改善，且不再静音/KeyError），
  而 CV2 历史 RTF 1~2（用户亲测"good"）。
- 已落地：cosyvoice.py 模型加载处新增 TF32 + cuDNN benchmark 开关（零风险，边际加速，
  py_compile 通过）。无法消除 WDDM 逐 token 开销。
