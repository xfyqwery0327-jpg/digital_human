- 修复：`server9/tts/qwen.py` 新增 `_install_sdpa_mask_fix()`（clone 后再 `|=`，同时替换模块级 `sdpa_mask` 与 `AttentionMaskInterface._global_mapping["sdpa"]`），在 `_load_model()` 内安装。

## 联调脚本踩坑（scripts/test_robot_ask.py 已修）
1. websockets 11 的 `websockets.connect` 是 legacy 实现，只认 `extra_headers`；传 `additional_headers` 不报错但会被塞进 `**kwargs` 透传给 `loop.create_connection()`，**在 await 建连阶段才抛 TypeError**，外层 try/except 抓不到。
2. 从开发机/沙箱访问 `10.0.7.232`（现场默认 host）会被中间网络层直接 RST（GET /health 403、POST WinError 10054），服务端本身没事。已加 host 探测失败自动回退 127.0.0.1（`--no-host-fallback` 可关）+ POST 退避重试 2 次。
3. 上一轮没讲完时服务端按设计返回 409 `turn_in_progress`，不是脚本 bug；print_verdict 已加专门提示。
4. Windows 计划任务 `DigitalHuman` 提权托管服务，普通 shell `Stop-Process` 拒绝访问，要用 `Stop-ScheduledTask`/`Start-ScheduledTask`。

## cosyvoice3 全是杂音 —— 已定位到「LLM 生成的 speech token 是错的」，根因未明（用户选择暂缓，先切回 qwen3 跑联调）
证据链：
1. 声码器健康：参考音真实 token 直接喂 `token2wav`，ASR 完美还原参考句（tests/cv3_vocoder_check.py）。
2. LLM 数学健康：sdpa 与 eager 输出完全一致 cosine=1.0000，权重 strict=True 无 missing/unexpected（tests/cv3_attn_ab.py）。
3. 官方 asset/zero_shot_prompt.wav + README 示例文本也出杂音 → 与人设数据、server9 手拼路径、调用方式无关（tests/cv3_groundtruth.py）。
4. `llm.rl.pt` 同样失败 → 不是 checkpoint 问题（tests/cv3_rlcheck.py）。
5. 生成 token 分布与真实语音 token 严重不符：JS 0.59 bits、top50 仅重合 3/50、明显偏向低 ID（tests/cv3_tokdiag.py）。
6. 环境 transformers 4.57.3，官方 requirements.txt 要求 4.51.3 —— 版本不一致，当前最大嫌疑。
7. onnxruntime CUDA EP 加载失败（缺 cudnn64_9.dll），campplus/speech_tokenizer 跑在 CPU；token 数量与声码器还原均正常，暂判定不影响音质。
